# ПРОЕКТИРОВАНИЕ БАЗЫ ДАННЫХ

## Part 1: Выбор сценария

Для данной работы выбран сценарий: **Система бронирования в ресторане**. Эта система будет управлять бронированиями клиентов, столиками, персоналом и пунктами меню.

Цели и задачи:

-   **Назначение и учёт персонала.** Каждое бронирование закрепляется за конкретным сотрудником, что упрощает контроль качества и распределение задач.

-   **Управление загрузкой зала.** Ресторан получает актуальную информацию о занятости столов на конкретное время, что позволяет оптимально распределять гостей.

-   **Автоматизация процесса бронирования.** Система позволяет фиксировать бронирования столиков в электронном виде, минимизируя риск человеческой ошибки.

-   **Сбор и анализ истории клиентов.** Система накапливает историю посещений, что позволяет отслеживать предпочтения гостей, их любимые блюда и частоту визитов.

## Part 2: Проектирование базы данных и документация

### Идентификация сущностей и атрибутов

1. Клиенты (*Customers*)
2. Столики (*RestaurantTables*)
3. Бронь (*Reservations*)
4. Персонал (*Staff*)
5. Меню (*Menu*)

---

### Проектирование таблиц

#### 1. Table Name: Customers

**Description:** Хранение информации о клиентах.

**Attributes:**

| Атрибут | Тип данных | Ограничения |
|---------|-----------|-------------|
| CustomerID | INTEGER | PK |
| FirstName | VARCHAR(100) | NOT NULL |
| LastName | VARCHAR(100) | NOT NULL |
| Phone | VARCHAR(20) | NOT NULL, UNIQUE |
| Email | VARCHAR(255) | UNIQUE |

**Constraints:**

- `PK_Customers`: PRIMARY KEY (CustomerID)
- `UQ_CustomerPhone`: UNIQUE (Phone)
- `UQ_CustomerEmail`: UNIQUE (Email)

---

#### 2. Table Name: RestaurantTables

**Description:** Хранение информации о столиках.

**Attributes:**

| Атрибут | Тип данных | Ограничения |
|---------|-----------|-------------|
| TableID | INTEGER | PK |
| TableNumber | INTEGER | NOT NULL, UNIQUE |
| Capacity | INTEGER | NOT NULL |
| Location | VARCHAR(50) | NOT NULL |

**Constraints:**

- `PK_RestaurantTables`: PRIMARY KEY (TableID)
- `UQ_TableNumber`: UNIQUE (TableNumber)
- `CHK_Capacity`: CHECK (Capacity >= 1)

---

#### 3. Table Name: Reservations

**Description:** Информация о брони.

**Attributes:**

| Атрибут | Тип данных | Ограничения |
|---------|-----------|-------------|
| ReservationID | INTEGER | PK |
| CustomerID | INTEGER | FK (REFERENCES Customers), NOT NULL |
| TableID | INTEGER | FK (REFERENCES RestaurantTables), NOT NULL |
| CreatedByStaffID | INTEGER | FK (REFERENCES Staff), NOT NULL |
| AssignedWaiterID | INTEGER | FK (REFERENCES Staff), NOT NULL |
| ReservationDateTime | TIMESTAMP | NOT NULL, DEFAULT CURRENT_TIMESTAMP |
| DurationHours | INTEGER | NOT NULL, DEFAULT 3 |
| ReservationStatus | ENUM ('confirmed', 'cancelled', 'completed') | NOT NULL, DEFAULT 'confirmed' |

**Constraints:**

- `PK_Reservations`: PRIMARY KEY (ReservationID)
- `FK_Res_Customer`: FOREIGN KEY (CustomerID) REFERENCES Customers (CustomerID)
- `FK_Res_Table`: FOREIGN KEY (TableID) REFERENCES RestaurantTables (TableID)
- `FK_Res_CreatedBy`: FOREIGN KEY (CreatedByStaffID) REFERENCES Staff (StaffID)
- `FK_Res_Waiter`: FOREIGN KEY (AssignedWaiterID) REFERENCES Staff (StaffID)
- `CHK_ReservationDateTime`: CHECK (ReservationDateTime >= CURRENT_TIMESTAMP)
- `CHK_Duration`: CHECK (DurationHours >= 1)

### Взаимосвязи

#### 1. Customers и Reservations (Один-ко-Многим)

Один клиент может оформить множество бронирований, но каждое бронирование относится к одному конкретному клиенту.

- `Reservations.CustomerID` является внешним ключом (FK), ссылающимся на `Customers.CustomerID`.

#### 2. RestaurantTables и Reservations (Один-ко-Многим)

Один стол может быть забронирован множество раз в разное время, но каждое бронирование относится к одному конкретному столу.

- `Reservations.TableID` является внешним ключом (FK), ссылающимся на `RestaurantTables.TableID`.

#### 3. Staff и Reservations (CreatedBy) (Один-ко-Многим)

Один сотрудник может создать множество бронирований, но каждое бронирование создано одним конкретным сотрудником.

- `Reservations.CreatedByStaffID` является внешним ключом (FK), ссылающимся на `Staff.StaffID`.

#### 4. Staff и Reservations (AssignedWaiter) (Один-ко-Многим)

Один официант может быть назначен на обслуживание множества бронирований, но каждое бронирование закреплено за одним конкретным официантом.

- `Reservations.AssignedWaiterID` является внешним ключом (FK), ссылающимся на `Staff.StaffID`.

#### 5. Reservations и Menu (Многие-ко-Многим)

Одно бронирование может содержать произвольное количество позиций из меню, в то время как одно и то же блюдо может входить в состав множества различных бронирований.

Для реализации связи многие-ко-многим была введена промежуточная сущность — **OrderItems** (Позиции заказа), которая разбила исходную связь на две независимые связи типа **один-ко-многим (1:N)**:

- `OrderItems.ReservationID` является внешним ключом (FK), ссылающимся на `Reservations.ReservationID`.
- `OrderItems.ItemID` является внешним ключом (FK), ссылающимся на `Menu.ItemID`.

## SQL-код

```sql
CREATE TABLE Customers (
    CustomerID INTEGER,
    FirstName VARCHAR(100) NOT NULL,
    LastName VARCHAR(100) NOT NULL,
    Phone VARCHAR(20) NOT NULL,
    Email VARCHAR(255)
);

ALTER TABLE Customers
    ADD CONSTRAINT PK_Customers PRIMARY KEY (CustomerID),
    ADD CONSTRAINT UQ_CustomerPhone UNIQUE (Phone),
    ADD CONSTRAINT UQ_CustomerEmail UNIQUE (Email);

CREATE TABLE RestaurantTables (
    TableID INTEGER,
    TableNumber INTEGER NOT NULL,
    Capacity INTEGER NOT NULL,
    Location VARCHAR(50) NOT NULL
);

ALTER TABLE RestaurantTables
    ADD CONSTRAINT PK_RestaurantTables PRIMARY KEY (TableID),
    ADD CONSTRAINT UQ_TableNumber UNIQUE (TableNumber),
    ADD CONSTRAINT CHK_Capacity CHECK (Capacity >= 1);

CREATE TABLE Staff (
    StaffID INTEGER,
    FirstName VARCHAR(100) NOT NULL,
    LastName VARCHAR(100) NOT NULL,
    Role VARCHAR(20) NOT NULL,
    Phone VARCHAR(20) NOT NULL,
    HireDate DATE NOT NULL DEFAULT CURRENT_DATE
);

ALTER TABLE Staff
    ADD CONSTRAINT PK_Staff PRIMARY KEY (StaffID),
    ADD CONSTRAINT UQ_StaffPhone UNIQUE (Phone);

CREATE TABLE Menu (
    ItemID INTEGER,
    Name VARCHAR(100) NOT NULL,
    Category VARCHAR(50) NOT NULL,
    Price DECIMAL(8,2) NOT NULL,
    Description TEXT
);

ALTER TABLE Menu
    ADD CONSTRAINT PK_Item PRIMARY KEY (ItemID),
    ADD CONSTRAINT UQ_ItemName UNIQUE (Name),
    ADD CONSTRAINT CHK_Price CHECK (Price >= 0);

CREATE TABLE Reservations (
    ReservationID INTEGER,
    CustomerID INTEGER NOT NULL,
    TableID INTEGER NOT NULL,
    CreatedByStaffID INTEGER NOT NULL,
    AssignedWaiterID INTEGER NOT NULL,
    ReservationDateTime TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    DurationHours INTEGER NOT NULL DEFAULT 3,
    ReservationStatus VARCHAR(20) NOT NULL DEFAULT 'confirmed'
);

ALTER TABLE Reservations
    ADD CONSTRAINT PK_Reservations PRIMARY KEY (ReservationID),
    ADD CONSTRAINT CHK_ReservationDateTime CHECK (ReservationDateTime >= CURRENT_TIMESTAMP),
    ADD CONSTRAINT CHK_Duration CHECK (DurationHours >= 1),
    ADD CONSTRAINT CHK_ReservationStatus CHECK (ReservationStatus IN ('confirmed', 'cancelled', 'completed')),
    ADD CONSTRAINT FK_Res_Customer FOREIGN KEY (CustomerID) REFERENCES Customers(CustomerID),
    ADD CONSTRAINT FK_Res_Table FOREIGN KEY (TableID) REFERENCES RestaurantTables(TableID),
    ADD CONSTRAINT FK_Res_CreatedBy FOREIGN KEY (CreatedByStaffID) REFERENCES Staff(StaffID),
    ADD CONSTRAINT FK_Res_Waiter FOREIGN KEY (AssignedWaiterID) REFERENCES Staff(StaffID);

CREATE TABLE OrderItems (
    OrderItemID INTEGER,
    ReservationID INTEGER NOT NULL,
    ItemID INTEGER NOT NULL,
    Quantity INTEGER NOT NULL,
    UnitPrice DECIMAL(8,2) NOT NULL,
    SpecialRequests VARCHAR(100) NOT NULL DEFAULT '',
    OrderItemStatus VARCHAR(20) NOT NULL DEFAULT 'confirmed',
    CreatedAt TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

ALTER TABLE OrderItems
    ADD CONSTRAINT PK_OrderItem PRIMARY KEY (OrderItemID),
    ADD CONSTRAINT CHK_Quantity CHECK (Quantity > 0),
    ADD CONSTRAINT CHK_OrderItemStatus CHECK (OrderItemStatus IN ('confirmed', 'cancelled', 'completed')),
    ADD CONSTRAINT FK_Ord_Reserv FOREIGN KEY (ReservationID) REFERENCES Reservations(ReservationID),
    ADD CONSTRAINT FK_Ord_Item FOREIGN KEY (ItemID) REFERENCES Menu(ItemID);
```
